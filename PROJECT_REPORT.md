# Heart Health Monitor: Project Report and LLM Context

## 1. Executive Summary

Heart Health Monitor is an academic heart-disease analytics application. It combines:

1. **Supervised learning**: five models estimate the chance that a patient belongs to the heart-disease class.
2. **Unsupervised learning**: K-Means groups patients by similarity in clinical features, and PCA projects those groups into two dimensions for visualization.
3. **A web interface**: a Flask API serves serialized scikit-learn artifacts, while a vanilla HTML/CSS/JavaScript frontend provides prediction and clustering dashboards.

The application is a demonstration and is explicitly **not a medical diagnostic tool**. It has no authentication, authorization, database, user accounts, persistence, or production deployment configuration.

## 3. End-to-End Architecture

```text
Browser
  │
  │ HTTP JSON requests
  ▼
frontend/index.html + script.js
  │  fetch() to http://127.0.0.1:5000
  ▼
Flask backend/app.py
  │
  ├── StandardScaler + supervised estimators
  ├── unsupervised StandardScaler + KMeans + PCA
  └── JSON metadata and precomputed plot points
       ▲
       │ generated by
model_training/train_supervised.py

```

At startup, Flask loads every model and JSON artifact once. Each request only performs feature extraction, scaling, inference, and JSON serialization. The frontend is static and must be served separately because browser `fetch()` calls from a `file://` page are restricted.

## 4. Dataset and Feature Contract

The input file is the classic UCI Cleveland heart-disease dataset. It contains 13 input features and a binary `target` column. The training scripts expect these exact feature names and order:

| Position | Feature | Meaning / UI representation |
|---:|---|---|
| 1 | `age` | Age in years |
| 2 | `sex` | Encoded sex: 1 male, 0 female |
| 3 | `cp` | Chest-pain category, encoded 1-4 |
| 4 | `trestbps` | Resting blood pressure |
| 5 | `chol` | Serum cholesterol |
| 6 | `fbs` | Fasting blood sugar above 120 mg/dl, 0/1 |
| 7 | `restecg` | Resting ECG category, encoded 0-2 |
| 8 | `thalach` | Maximum heart rate achieved |
| 9 | `exang` | Exercise-induced angina, 0/1 |
| 10 | `oldpeak` | ST depression induced by exercise |
| 11 | `slope` | ST-segment slope, encoded 1-3 |
| 12 | `ca` | Number of major vessels colored, 0-3 |
| 13 | `thal` | Thalassemia result, encoded 0-2 in the form |

`target` is used only as the supervised label. The backend never accepts `target` from the client. It constructs a one-row NumPy array by reading every field listed in `feature_order.json`.

The backend converts all values to `float`. Missing fields return HTTP 400 with an error, and non-numeric values return HTTP 400. The backend does not enforce the UI's min/max ranges or validate categorical values, so API clients can submit numerically valid but clinically invalid values.

## 5. Supervised Training Pipeline

`model_training/train_supervised.py` performs the following steps:

1. Reads `data/heart.csv` with pandas.
2. Selects the 13 features in `FEATURE_ORDER` and uses `target` as `y`.
3. Splits the data into 80% training and 20% test data with `random_state=42` and stratification.
4. Fits a `StandardScaler` on training data only and transforms training/test features.
5. Trains five estimators:
   - `LinearRegression`
   - `LogisticRegression(max_iter=1000, random_state=42)`
   - `KNeighborsClassifier(n_neighbors=7)`
   - `DecisionTreeClassifier(max_depth=4, random_state=42)`
   - `SVC(probability=True, kernel="rbf", random_state=42)`
6. Calculates accuracy, precision, recall, F1, and a binary confusion matrix on the held-out test set.
7. Serializes each estimator, the scaler, the feature order, and metrics with joblib/JSON.

The README says “four” supervised models, but the implementation and runtime API use **five**, including linear regression.

## 6. Prediction Runtime Behavior

The `/predict` endpoint:

1. Parses JSON and extracts the 13 fields in the saved order.
2. Applies the supervised scaler.
3. Calls every loaded model.
4. For models with `predict_proba`, uses class-1 probability multiplied by 100.
5. For linear regression, treats its continuous prediction as a probability, multiplies by 100, and clips to 0-100.
6. Assigns a bucket: below 34 is `Low chance`, below 67 is `Moderate chance`, otherwise `High chance`.
7. Averages all five percentages equally into `overall_chance_percent`.

The response shape is:

```json
{
  "models": {
    "linear_regression": {"chance_percent": 42.1, "bucket": "Moderate chance"},
    "logistic_regression": {"chance_percent": 40.0, "bucket": "Moderate chance"},
    "knn": {"chance_percent": 57.1, "bucket": "Moderate chance"},
    "decision_tree": {"chance_percent": 25.0, "bucket": "Low chance"},
    "svm": {"chance_percent": 44.0, "bucket": "Moderate chance"}
  },
  "overall_chance_percent": 41.6,
  "overall_bucket": "Moderate chance"
}
```

The “overall” value is a simple arithmetic mean, not a separately trained ensemble or calibrated clinical probability. Linear regression is also not intrinsically a probability model; its output is being used as a score by convention.

## 7. Unsupervised Training Pipeline

`model_training/train_unsupervised.py` uses the same 13 features but excludes `target` during clustering:

1. Reads the CSV and selects the feature columns.
2. Fits a new `StandardScaler` on all 297 rows.
3. Calculates K-Means inertia for `k=1` through `k=8` and saves it for an elbow-method presentation chart.
4. Fits final `KMeans(n_clusters=2, random_state=42, n_init=10)`.
5. Fits `PCA(n_components=2)` for a 2D plot.
6. Only after clustering, examines the actual target values to calculate each cluster's disease rate.
7. Ranks clusters by disease rate and assigns interpretive labels: Low, High.
8. Saves cluster summaries, all 2D points, and the K-Means/PCA/scaler artifacts.

The current checked-in summary is:

| Cluster ID | Interpretive label | Average disease rate | Size |
|---:|---|---:|---:|
| 0 | Low chance | 20.5% | 185 |
| 1 | High chance | 88.4% | 112 |

Cluster IDs are arbitrary K-Means identifiers. The labels are assigned by ranking disease rates, so a future retraining can change which numeric ID means Low, Moderate, or High.

## 8. Clustering Runtime Behavior

The `/cluster` endpoint extracts and scales the submitted patient features with the separate unsupervised scaler, predicts a K-Means cluster, transforms the point with PCA, and returns the numeric ID, ranked label, group disease rate, and 2D coordinates.

The `/cluster-data` endpoint returns all precomputed patient points and the cluster summary. Each point includes `x`, `y`, `cluster`, `cluster_label`, and `actual_target`. Because the actual target is included in this visualization artifact, it is suitable for an academic demonstration but should be treated as sensitive ground-truth metadata in any real deployment.

The UI displays K=2 and Euclidean distance as disabled controls. These are descriptive controls only; the browser cannot change the trained K-Means configuration.

## 9. Flask API Contract

| Route | Method | Behavior |
|---|---|---|
| `/health` | GET | Returns `{ "status": "ok" }`. |
| `/predict` | POST | Runs all five supervised models and returns per-model and average chance scores. |
| `/metrics` | GET | Returns the saved supervised metrics JSON. |
| `/cluster` | POST | Assigns one patient to a K-Means cluster and returns PCA coordinates. |
| `/cluster-data` | GET | Returns all precomputed PCA points and cluster summaries. |

Flask-CORS is enabled globally. The API has no authentication, rate limiting, request-size policy, schema library, logging strategy, or error handler for malformed JSON beyond the local feature checks. The app starts Flask with `debug=True` on port 5000.

`MODELS_DIR = "models"` is relative to the process working directory. Therefore the documented command must run from `backend/`; starting `app.py` from the repository root can fail to locate the model files.

## 10. Frontend Behavior

The current UI is a single-page dashboard with two tab panels:

### Supervised Dashboard

- Collects all 13 model features through numeric fields and selects.
- Keeps seven advanced fields in a collapsible accordion.
- Sends the form as JSON to `/predict`.
- Shows an animated SVG gauge for the overall average.
- Renders one breakdown card for each returned model.
- Loads `/metrics` on page startup and renders an offline Chart.js accuracy bar chart.
- Stores the most recent payload in `window.lastPatientPayload` for later clustering.

### Unsupervised Analytics

- Lazy-loads `/cluster-data` the first time the tab opens.
- Shows cluster profile rows sorted by average disease rate.
- Renders a Chart.js scatter plot of the PCA points.
- Sends the last prediction payload, or the current form values, to `/cluster`.
- Adds a highlighted “You” point to the scatter plot.
- Provides client-side zoom and reset controls.
- Exports the current patient payload as a downloaded JSON file. This is not an export of the full cluster dataset despite the generic “Export Data” label.

The API base URL is hard-coded as `http://127.0.0.1:5000`, so deployment to another host requires editing `frontend/script.js` or introducing configuration.

## 13. Strengths

- Clear educational contrast between labeled prediction and unlabeled pattern discovery.
- Fixed feature-order artifact reduces training/inference column-order mistakes.
- Scalers are fitted during training and reused during inference.
- Training and runtime concerns are separated.
- Model metrics and clustering metadata are exposed through simple JSON APIs.
- The frontend can run without a frontend build system and uses a local Chart.js bundle.

## 14. Limitations and Risks

- The dataset is small and the evaluation uses one hold-out split.
- Reported model outputs are not clinical probabilities and are not calibrated.
- Linear regression is treated as a probability source even though it is a regression model.
- The equal-weight average has no learned ensemble justification.
- Categorical numeric encodings are treated as ordinary numeric values by several models.
- No missing-value, range, categorical-domain, or semantic validation exists in the backend.
- The app has open CORS, no authentication, debug mode enabled, and no production server configuration.
- Cluster labels depend on the target after clustering and are interpretive descriptions, not causal medical categories.
- PCA axis titles in the frontend are hard-coded as 42% and 18%; they are not read dynamically from the saved PCA artifact.
- Retrained artifacts can become inconsistent if only one training script is run or files are not copied to `backend/models`.
- The checked-in `backend/models` and `model_training/models` are duplicated, creating a synchronization risk.
- The frontend contains older HTML reference files that are not part of the active runtime path.

## 15. Recommended Future Improvements

1. Replace linear regression with a calibrated classifier or explicitly present it as a score.
2. Use cross-validation and report confidence intervals or repeated-split results.
3. Add a formal request schema and backend validation for ranges and categorical domains.
4. Move API URL and model directory settings into environment/configuration variables.
5. Add automated API and frontend smoke tests.
6. Disable Flask debug mode and restrict CORS in any non-local deployment.
7. Generate PCA variance labels from the saved PCA object instead of hard-coding them.
8. Use a single artifact build/copy command or package artifacts so training and runtime cannot drift.
9. Remove actual labels from public visualization responses unless they are required for the demonstration.
10. Add fairness, calibration, privacy, and clinical-review documentation before considering any real-world use.

## 16. One-Paragraph LLM Brief

This is a small Flask plus vanilla JavaScript academic heart-disease analytics demo using the UCI Cleveland dataset. Two Python scripts train separate pipelines: supervised models use 13 clinical features, a train-only StandardScaler, and five estimators whose test metrics are saved as JSON; unsupervised training uses a separate full-data StandardScaler, K-Means with fixed `k=2`, and PCA to create labeled-by-post-hoc-disease-rate patient clusters and 2D plot points. Flask loads duplicated serialized artifacts from `backend/models` and exposes `/predict`, `/metrics`, `/cluster`, `/cluster-data`, and `/health`; the browser dashboard sends form JSON to that API, renders prediction probabilities and metrics, lazy-loads the cluster map, highlights the submitted patient, and exports the current payload. The application has no authentication or persistence, runs locally on ports 5000 and 8080, uses relative runtime paths, and must be treated as an educational visualization rather than a medical diagnostic system.
